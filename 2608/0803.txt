Mock API Gateway の新 ALB 対応について、現時点での認識を整理しました。

まず、新 ALB 側に Mock API Gateway 用の Listener Rule と Target Group を作成するだけでは不十分であり、既存の Mock API Gateway の ECS Service についても、旧 ALB 側の Target Group から新 ALB 側の Target Group へ切り替える必要があると考えております。

そのうえで、実装方法としては、以下の 2 案が考えられます。

案 1：既存の運用方法を維持する
CDK では、初回デプロイ時に新 ALB 用の Mock API Gateway の Listener Rule および Target Group のみを作成する
あるいは、これらのリソースを AWS 上で手動作成する
Mock API Gateway の ECS Service 更新は、従来どおり既存の YAML を使用して実施する
コンテナイメージについても、従来どおり手動で ECR に push する

この場合、今回の CDK 側の改修範囲を比較的小さく抑えられる一方、新 ALB 用 Target Group への ECS Service の切り替えを、既存の YAML または手動運用で実施する必要があります。

案 2：Mock API Gateway の更新も CDK 管理へ移行する

今回の対応に合わせて、Mock API Gateway のデプロイおよび更新も CDK 管理へ移行する案です。

この場合は、既存 YAML に定義されている Mock API Gateway 関連のパラメータ、ECS Service、Task Definition、Log Group、Target Group、Listener Rule などを調査・整理したうえで、CDK 側に同等の定義を実装する必要があります。

そのため、案 1 と比較すると、改修範囲および確認項目が多くなり、相応の追加工数が発生する見込みです。

現時点では、どちらの案を採用する場合でも、新 ALB に Listener Rule と Target Group だけを追加して完了とすることは難しく、ECS Service の接続先を新 Target Group へ切り替える対応が必要になると認識しております。

今回の対応については、既存運用を維持して短期間で進めるか、あるいはこの機会に Mock API Gateway も CDK 管理へ移行するか、それぞれのメリット・デメリットおよび今後の運用性を踏まえて判断する必要があると考えております。

特に、現在の工期がすでに当初予定より遅れている状況であるため、実装を先行する前に、改修範囲と納期への影響を含めて、プロジェクトリーダーおよび関係者の皆様にご相談のうえ、方針を決定させていただければと思います。

方針が確定しましたら、その内容に合わせて具体的な実装方法と作業範囲を整理いたします。
