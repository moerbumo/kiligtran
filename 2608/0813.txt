## R-05: ECS サービス（ChannelAdapter）削除

| 列 | 内容 |
|---|---|
| パターンID | R-05 |
| リソース | ・{ENV}_{channel}_channeladapter_{A｜B} |
| 面区分 | A/B |
| 改修パターン | 削除 |
| 変更内容の詳細 | 対象チャネル（例：FCM）を利用するクライアントが存在しなくなったことを事前に確認したうえで、廃止バイプライン実行時点で対象チャネルのCDKコード側の定義を削除（非稼働面デプロイ時点では該当チャネルは更新されず、後続の廃止バイプラインでA/B両面の対象スタックを削除）。CodePipeline等の自動化パイプラインでは卸下できないため、CDKコード削除後は**運用担当者が手動でCloudFormationスタックを削除**する。 |
| 考慮事項 | ①廃止バイプライン実行時点で、全クライアントが当該チャネルへの新規リクエストを送信していないことを事前に確認する必要がある（配信中クライアントが存在する状態でスタックを削除すると異常終了、または配信中リクエストの消失につながる）<br>②他チャネルのChannelAdapter・共通リソース（channelreceiver、batch等）には影響を与えない<br>③手動でのスタック削除となるため、削除順序・削除範囲（Alarm/Dashboard/LogGroup等の連動リソース含む）を運用手順書に明記し、削除漏れ・誤削除を防止する<br>④当該チャネル利用停止について、事前に全クライアント・関係者へ合意・周知しておくことが前提 |
| 無停止可否 | 可 |
| 理由・前提条件 | 廃止対象チャネル以外のリソースには影響を与えず、また廃止対象チャネル自身も事前調整により配信中リクエストが存在しない状態で削除されるため、サービス全体としては無停止を維持できる。ただし自動パイプラインでの卸下ができないため、手動削除作業に伴うヒューマンエラーのリスクは別途運用面で管理する必要がある。 |
| 判定 | 確定 |
